## 瓶颈分析

### 连接上限
- **稳定区间:** ≤30 pairs (60 并发 WS 连接)
- **最大实测:** 82 pairs (164 并发连接)
- **限制根因:** 
  1. Gateway 容器 `ulimit -n=1024`（已提升至 65536，但对串行连接无改善）
  2. go-zero 框架内部的 goroutine/连接调度上限
  3. 串行连接建立过程中早期连接因心跳超时断开

### 性能特征
- **消息吞吐:** 稳定 10 QPS (不限速)
- **端到端延迟:** 高度稳定，P99-P50 = 30ms (1.3%)
- **错误率:** 0% (所有连接成功的消息 100% 送达)
- **延迟瓶颈:** 消息在 Kafka 投递链路的固定延迟 ~2s

## 优化尝试 (已回滚)

1. **并行 WS 连接 (10 workers):** 连接成功率从 82 降至 22 pairs ❌
2. **并行 WS 连接 (50 workers):** 连接成功率从 82 降至 24 pairs ❌  
3. **ulimit 提升 (65536):** 对串行连接无改善 → 
4. **结论:** 瓶颈不在 client 端，而在 go-zero gateway 的 WS 连接管理

## 建议

1. **生产部署:** 建议单 gateway 实例承载 ≤100 并发 WS 连接
2. **水平扩展:** 多 gateway 实例 + 负载均衡可线性提升连接数
3. **连接池预热:** 在大规模压测前使用 ramp-up 逐步建立连接
4. **框架调优:** 检查 go-zero rest engine 的 MaxConns 配置
